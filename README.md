# WheelGrade — iOS packaging (Capacitor + GitHub Actions)

The iOS App Store build of WheelGrade. The PWA alone can't be submitted to
Apple — it needs a native wrapper. This project is that wrapper.

## What was chosen, and why

| Option | Verdict |
|---|---|
| **PWABuilder iOS** | Produces an Xcode project, not an IPA. PWABuilder's own FAQ: "Can I publish to the App Store without a Mac? No, not currently." Its iOS template is labeled **Experimental** and community-maintained — the README says PWABuilder devs will not maintain iOS functionality. Still needs a Mac to build. Rejected. |
| **Capacitor + GitHub Actions macOS runner** | **Chosen.** Capacitor 8 generates the Xcode project on Linux (`npx cap add ios` works here — it uses Swift Package Manager, no CocoaPods). The build/sign/upload runs on a GitHub-hosted macOS runner with Xcode 26, so no Mac is needed at all. Actively maintained, the standard path for PWA-to-App-Store. |
| **Codemagic / MacinCloud** | Viable fallbacks. Codemagic gives 500 free macOS minutes/month and has Ionic support. GitHub Actions was chosen because Jon already lives on GitHub (the landing repo) and public repos get free macOS minutes. |

## How the app works

- **Bundle ID:** `com.wheelgrade.app` (matches the Apple Developer App ID
  already registered for Sign in with Apple).
- **Team ID:** `QWK64596Q9` (in `ExportOptions.plist` and the workflow).
- **The app loads the LIVE site** (`server.url: https://wheelgrade.com/app/`).
  Web deploys via the Worker go live in the iOS app immediately — no App
  Store resubmission for web changes. The bundled `web/` snapshot is a
  fallback only. This is the standard Capacitor "hosted app" pattern.
- **No native plugins.** The web app needs only localStorage, fetch, and the
  service worker — all work in WKWebView. Nothing to add.
- **Deployment target:** iOS 15.0. Built with Xcode 26 / iOS 26 SDK, which
  Apple has required for App Store Connect uploads since April 2026.
- **Icons:** full AppIcon set + splash are **generated at build time** by
  `scripts/gen_icons.py` (Pillow) — no PNGs are committed. The logo is
  the black + bright-green-W mark, drawn from the same vector coordinates
  as the shipped PWA icon. The workflow runs the script before `cap sync`.

## What's in this project

| Path | What it is |
|---|---|
| `capacitor.config.ts` | App ID, name, `webDir: web`, `server.url` → live site |
| `ios/` | The Xcode project (`ios/App/App.xcodeproj`, scheme `App`). Generated by `npx cap add ios`, committed. The copied `web/` inside it and generated config are gitignored — `cap sync` rebuilds them. |
| `android/` | The Android project (`android/app`, Gradle wrapper, `variables.gradle`). Generated by `npx cap add android`, committed. Same pattern as iOS: the copied `web/` and generated config are gitignored — `cap sync` rebuilds them. |
| `web/` | Snapshot of the Worker's `public/` (synced by `./sync-web.sh`). Committed so CI has it. |
| `assets/icon.png`, `assets/splash.png` | 1024 icon + 2732 splash — generated by `scripts/gen_icons.py`, not committed |
| `scripts/gen_icons.py` | Draws the AppIcon set, splash, web/ icons, and the Android launcher icons + splash screens from the vector logo (Pillow); run by the workflows before `cap sync` |
| `ExportOptions.plist` | Archive export settings (app-store-connect, automatic signing, team `QWK64596Q9`) |
| `.github/workflows/ios-testflight.yml` | The iOS cloud build: macOS runner → archive → export IPA → upload to TestFlight. Manual trigger only. |
| `.github/workflows/android-play.yml` | The Android cloud build: Ubuntu runner → JDK 21 → signed AAB + APK → artifacts. Manual trigger only. Upload the AAB to Play Console by hand. |
| `ANDROID.md` | Android runbook: secrets, build, Play Console upload. |
| `sync-web.sh` | Copies `~/workspace/wheelgrade-cloudflare/public/` → `web/`. Run before a release, then commit. |

## What Jon needs to do (in order)

### 1. Create the GitHub repo and push this project
Muse (the GitHub App) cannot create repos — Jon creates it.
- GitHub → New repository: **`kainjon/wheelgrade-ios`**, **Public**
  (public repos get free macOS runner minutes; private repos bill macOS at 10×).
- Push this folder to `main`. (Ask Muse to push once the repo exists.)

### 2. Create the App Store Connect API key (for signing + upload)
No certificate files to export — Apple manages the distribution cert and
provisioning profile automatically from this key.
- App Store Connect → Users and Access → **Integrations** → App Store
  Connect API → **Generate API Key**.
- Name: `WheelGrade CI`. Role: **Admin** (needs to create/upload builds).
- **Download the `.p8` file immediately** — it can only be downloaded once.
- Note the **Key ID** and the **Issuer ID** (shown at the top of the Keys page).
- Add three secrets to the repo (Settings → Secrets and variables →
  Actions → New repository secret):
  - `APP_STORE_CONNECT_API_KEY_ID` — the Key ID
  - `APP_STORE_CONNECT_API_ISSUER_ID` — the Issuer ID
  - `APP_STORE_CONNECT_API_KEY_P8` — the full contents of the `.p8` file,
    including the `-----BEGIN PRIVATE KEY-----` / `-----END PRIVATE KEY-----` lines

### 3. Create the app record in App Store Connect
- App Store Connect → My Apps → **+** → New App.
- Platform: **iOS**. Name: **WheelGrade**. Primary language: English.
- Bundle ID: select **`com.wheelgrade.app`** (already registered; if it
  isn't listed, register it first in Apple Developer → Certificates,
  Identifiers & Profiles → Identifiers → App IDs).
- SKU: anything unique, e.g. `wheelgrade-001`. User Access: Full Access.

### 4. Run the build
- GitHub repo → **Actions** → "iOS — Build & Upload to TestFlight" →
  **Run workflow**.
- It picks Xcode 26, installs deps, syncs Capacitor, archives, exports the
  IPA, and uploads to TestFlight. The IPA is also kept as a workflow
  artifact. Build number auto-increments from the GitHub run number.
- First run: Apple creates the distribution certificate + provisioning
  profile automatically (that's the `-allowProvisioningUpdates` flag).
  If it fails on signing, the error will say exactly which permission or
  record is missing.

### 5. TestFlight, then the store listing
- App Store Connect → TestFlight: the build appears after Apple processes
  it (~10–30 min). Install on Jon's iPhone via the TestFlight app and test.
- **Screenshots** (needed for the listing, Jon takes these from the
  TestFlight build on his iPhone): 6.5" iPhone, 5.5" iPhone, and iPad.
  Suggested shots: Analyzer (A grade), Board, Portfolio.
- **Listing details** (Jon writes these): app description, keywords,
  support URL (`https://wheelgrade.com/support.html`), privacy policy URL
  (`https://wheelgrade.com/privacy.html`), and review notes (a test account
  or a note that the first 3 grades are free, then $9.99).

## ⚠️ The one thing that will likely block App Store review: payment

The web app sells the $9.99 unlock through a **Stripe Payment Link**.
Apple Guideline 3.1.1 requires digital purchases inside an app to use
**In-App Purchase** — apps that send users to an external payment page for
an in-app unlock are routinely rejected. The Stripe-only flow will very
likely fail review.

The fix (not done here — it's a product decision, not packaging): add
Apple In-App Purchase for the $9.99 unlock in the iOS app (via a Capacitor
IAP plugin or RevenueCat), and keep Stripe for the web. The iOS app can be
built and TestFlight-tested now; the IAP work lands before the store
submission. Decide this before spending time on screenshots/review notes.

## Updating the app later

- **Web changes** (Analyzer, Board, copy, grades): deploy the Worker as
  usual. The iOS app loads the live site — no rebuild, no resubmission.
- **Native changes** (icon, splash, bundle ID, permissions, Capacitor
  version): edit here, run `./sync-web.sh` if the web snapshot changed,
  commit, and re-run the workflow. A new TestFlight build goes out.
- **If Apple bumps the Xcode floor** (today it's Xcode 26): update the
  "Select Xcode 26" step in the workflow and the `macos-15` runner image.
